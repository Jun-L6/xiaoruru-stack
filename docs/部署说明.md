# 部署说明

## 1. 功能与依赖

所有业务经由 Nginx UI 容器内的 Nginx 访问。启动任一业务，管理器会先启动网关并确认其健康。博客与 CPA 可以独立启动、停止；选择 CPA 作为博客 AI 接口不会让博客自动启动 CPA。

| 功能 | 容器 | 公网入口 |
| --- | --- | --- |
| gateway | nginx-ui | 80/TCP、443/TCP |
| vpn | xui | 8443/TCP（Reality）、8443/UDP（Hysteria2） |
| vpn 的可选正向代理 | gost | 9443/TCP |
| cpa | cli-proxy-api、cpa-manager-plus | 通过网关 443 访问 |
| blog | rurublog | 通过网关 443 访问 |
| tools | certbot、panel-init | 一次性执行，完成即移除 |

不要公开 2053、2096、8317、18317、8080、9000。GOST 是 HTTPS 正向代理，直接使用 9443，不经过 Nginx HTTP 反代。

## 2. 服务器准备

推荐 Ubuntu 24.04、Docker Engine 与 Docker Compose 插件。Compose 最低 2.24.4，Python 最低 3.9。另需 bash、curl、OpenSSL；自动续期使用 systemd。

按 [Docker 官方 Ubuntu 安装指南](https://docs.docker.com/engine/install/ubuntu/)安装 Docker Engine 和 Compose 插件，检查：

```bash
docker version
docker compose version
python3 --version
curl --version
openssl version
```

服务器初始化和管理建议使用 root，以便设置博客数据目录 UID/GID 10001 和安装续期任务。不需要在宿主机安装 Java；仅在本地预编译博客时需要 JDK 21 和 Maven。

安全组允许 SSH、80/TCP、443/TCP。启用 VPN 时增加 8443/TCP 和 8443/UDP；启用 GOST 时增加 9443/TCP。主机防火墙也需允许对应端口。

Docker 发布端口可能不受普通 UFW 规则约束，服务是否暴露以 Compose 的发布端口和云安全组为准。

## 3. 域名

为启用的功能设置 A 记录，指向服务器公网 IPv4：

| 设置项 | 默认域名 | 用途 |
| --- | --- | --- |
| gateway | nginx-ui.xiaoruru.beer | Nginx UI |
| vpn | 3x-ui.xiaoruru.beer | 面板与订阅 |
| cpamp | cpa-mp.xiaoruru.beer | CPA Manager Plus |
| cpa_api | cli-proxy-api.xiaoruru.beer | CPA API |
| blog | xiaoruru.beer | 博客 |
| gost | www.xiaoruru.beer | 正向代理的 TLS 名称 |

只需要准备启用功能的域名，gateway 始终需要。没有可用 IPv6 时不要配置 AAAA 记录。初次部署使用 DNS 直连，确保 ACME 的 HTTP 请求能到达本机 80 端口。

## 4. 上传项目

将项目放到服务器 `/srv/xiaoruru-stack`。本机上传示例：

```bash
rsync -av \
  --exclude='.git' --exclude='.idea' --exclude='.DS_Store' \
  --exclude='data' --exclude='target' --exclude='__pycache__' \
  --exclude='.playwright-cli' --exclude='output' \
  -e 'ssh -i /Users/jun/Downloads/初始化搭建.pem' \
  /Users/jun/IdeaProjects/docker-xiaoruru/ \
  root@198.11.173.173:/srv/xiaoruru-stack/
```

进入服务器：

```bash
cd /srv/xiaoruru-stack
chmod +x bootstrap.sh
./bootstrap.sh init
```

初始化向导只询问启用功能、GOST 开关、域名和证书邮箱，不启动容器、不配置 CPA 上游、不配置博客模型。

账号与密钥自动生成。重复初始化保留已有私密配置和数据库。配置保存在 `data/system/config.json`，自动生成的 Compose 环境文件是 `data/system/compose.env`，不需要手工寻找或维护根目录 `.env`。

也支持提前准备配置文件：

```bash
cp config/defaults.json /root/xiaoruru-config.json
nano /root/xiaoruru-config.json
./bootstrap.sh init --config /root/xiaoruru-config.json
```

必须填写 email，按需修改 enabled、gost 和 domains。默认共享网络是 `xiaoruru-gateway`、子网 `172.30.60.0/24`。若与已有网络冲突，请在首次初始化前调整。初始化后不直接更换共享网络。

## 5. 准备博客镜像

### 方式 A：在服务器编译

```bash
./bootstrap.sh build blog
```

这只构建镜像，不启动博客。编译时的内存与 CPU 需求高于博客运行时，小内存服务器推荐方式 B。

### 方式 B：本地编译并导入服务器

在本机的项目根目录执行。以下针对服务器为 x86_64/amd64：

```bash
cd apps/blog
mvn -B -ntp clean verify
cd ../..
docker buildx build --platform linux/amd64 --target prebuilt \
  -t xiaoruru/rurublog:local --load ./apps/blog
docker save -o /tmp/xiaoruru-rurublog.tar xiaoruru/rurublog:local
scp -i /Users/jun/Downloads/初始化搭建.pem \
  /tmp/xiaoruru-rurublog.tar root@198.11.173.173:/srv/
```

服务器导入：

```bash
docker load -i /srv/xiaoruru-rurublog.tar
```

ARM64 服务器将构建平台改为 `linux/arm64`。可用服务器的 `uname -m` 确认架构。不要直接把 ARM 镜像当作 AMD64 镜像导入。

博客默认内存上限 768 MiB、CPU 上限 1 核、Java 最大堆 320 MiB、数据库连接池 4、Tomcat 最大线程 32；实际内存取决于文章、并发和 AI 请求。网关、VPN、CPA 会额外使用内存，整机不能只按博客限制估算。

## 6. 启动功能

```bash
./bootstrap.sh start vpn
./bootstrap.sh start cpa
./bootstrap.sh start blog
./bootstrap.sh status
```

任一 start 都会先准备共享网络和网关，申请配置中所有已启用域名需要的证书，再启动业务并启用对应反代。

也可执行：

```bash
./bootstrap.sh start all
```

all 只处理初始化时选择的功能。已安装的 CPA 只启动现有容器，不进入升级流程；未安装的 CPA 会进入官方安装器。

### VPN 首次初始化

第一次启动会自动配置管理账号、订阅和一个客户端，同时创建：

- VLESS + TCP + REALITY + Vision，8443/TCP。
- Hysteria2，8443/UDP。

REALITY 会检测候选握手目标，选择可用目标。失败时可检查服务器到目标站点的出站网络后重试。VPN 初始化完成后，普通 start 不会重设账号、不重复添加入站或客户端；日常调整在 3x-ui 完成。

订阅信息写入 `data/vpn/output/access.json`，包含 Shadowrocket/v2rayN 通用订阅及 Clash/Mihomo 订阅。该文件有访问凭据，不能公开。

### CPA 官方安装器

`start cpa` 会先生成：

```text
data/cpa/compose.override.yaml
```

然后从官方仓库下载安装器，进行 Bash 语法检查、显示 SHA-256，并继承当前终端交互执行。安装位置默认为 `data/cpa`，安装范围为 CPA + CPAMP，部署方式为 Docker。请保留这些值。

override 从第一次启动起生效：

- 去掉 8317、18317 的宿主机端口发布；
- CPA 两个服务保留自己的默认网络，并加入共享网关网络；
- Manager 的 /data 改为 `data/cpa/manager`；
- CPA 的配置、auths、日志、secret 和安装器生成文件保留在 `data/cpa`。

官方安装器负责 CPA 与 CPAMP 的内部管理连接及初始化。模型、上游账号、OAuth、普通 API Key 等进入管理页面配置，不由本项目的命令行向导设置。

重复执行 `start cpa`：

- 正在运行：进入官方安装器，由你选择升级、修复或退出。
- 已安装但停止：选择“启动现有容器”或“进入官方安装器”。
- 官方安装器退出或取消：不会代替你自动选择升级。

不使用 `update cpa`，没有后台自动升级任务。需要更新时运行 `start cpa` 并在官方菜单选择升级。适配只影响网络与挂载，使用官方镜像，不重新编译 CPA。

## 7. 登录和 AI

查看私密凭据：

```bash
less data/system/secrets.json
```

gateway_username/gateway_password 用于 Nginx UI；vpn_username/vpn_password 用于 3x-ui；blog_admin 是博客 admin 的登录密钥；gost_username/gost_password 用于正向代理。

博客实际配置位于 `data/blog/config/application.yml`。CPA 登录凭据以官方安装器输出为准，通常在 `data/cpa/secrets/`。请不要将上述文件、订阅 URL 或日志截图发到公共仓库。

博客进入 `https://xiaoruru.beer/admin` → “AI 设置”：

1. 关闭 AI：默认，不发起模型请求。
2. CPA：根地址固定为 `http://cli-proxy-api:8317`；填写普通 API Key、模型。
3. 外部模型：填写兼容接口根地址、路径、API Key、模型。

接口地址和路径直接拼接。例如根地址含 /v1 时，调用路径填 /chat/completions；根地址不含 /v1 时，填 /v1/chat/completions。

保存不探测接口，后续调用立即使用新设置。CPA 未启动、无上游、无模型或鉴权错误，只在真正调用时出错，不影响博客浏览、保存、发布。失败任务可在“AI 任务”中手动重试。

API Key 不回显，留空保留；更换外部地址必须重新填写。两个模式分别保存自己的配置。密钥加密存储，`data/blog/runtime/secrets/ai.key` 是解密所需文件。

## 8. Nginx UI 与证书

访问 `https://nginx-ui.xiaoruru.beer`。Nginx UI 不挂载 Docker Socket，已配置忽略该项检查；容器升级由本项目操作，站点配置在 Web 页面编辑。

默认配置使用 Docker 内部 DNS 解析后端，因此没有启动的业务不会阻止网关启动。已有站点文件的 Web 编辑不会被普通 start 覆盖。

共享证书名为 `xiaoruru-services`，由 Certbot 管理，网关、Hysteria2 和 GOST 读取同一份证书。不要用 Nginx UI 同时修改这份证书；证书目录对网关为只读。

安装每日检查与自动续期任务：

```bash
./bootstrap.sh tools timer
systemctl list-timers xiaoruru-cert-renew.timer
```

手动检查：

```bash
./bootstrap.sh tools renew
```

证书实际变化后才 reload Nginx 并 restart 正在运行的 xui/GOST。博客和 CPA 不需要重启。网关已停止时跳过定时任务，不会自动启动业务。普通停止功能不会从已有证书中移除域名。

新增子域名流程：

1. 先完成 DNS 解析。
2. `config <功能>` 修改对应入口域名，或 `init <功能>` 启用新功能。
3. `start gateway` 扩展证书。
4. 已有站点更换域名时，执行 `tools sites`，选择功能并确认重新生成。
5. 也可在 Nginx UI 中自行编辑站点。重新生成会覆盖该功能站点的手工编辑。

VPN 已初始化后更换域名，还需在 3x-ui 中更新订阅地址、两个入站的分享地址以及 Hysteria2 的 TLS serverName，并让客户端更新订阅；普通 start 不覆盖面板中的业务参数。

ACME 路径 `/.well-known/acme-challenge/` 在独立默认站点处理，不依赖博客、CPA 或 VPN 启动。

## 9. 管理命令

| 命令 | 行为 |
| --- | --- |
| `./bootstrap.sh` | 中文数字菜单；键盘操作；0 返回 |
| `status` | 只读查看容器状态与入口 |
| `init [功能]` | 生成配置、凭据和目录，不启动容器 |
| `config [功能]` | 调整部署开关和域名 |
| `start 功能` | 自动启动网关，再启动业务；普通功能可重复执行 |
| `stop 功能` | 停止该业务，保留数据和网关 |
| `stop all` | 确认后停止全部；无人值守可加 --yes |
| `restart 功能` | 重启现有容器，不拉取镜像 |
| `logs 功能` | 显示最近 120 行日志 |
| `doctor` | 校验 Compose、网关与 CPA 的网络/挂载结构 |
| `build blog` | 构建博客镜像 |
| `update gateway` / `update vpn` | 确认后拉取当前配置中的镜像并应用 |
| `tools` | 临时工具菜单 |

功能名为 gateway、vpn、cpa、blog；start/stop/restart 支持 all。停止 VPN 时会同时停止 GOST。仍有业务在运行时，不允许单独 stop gateway。

镜像版本在 `data/system/config.json` 的 images 中固定。update 拉取配置中的标签，不自动改成 latest；要调整版本，修改对应镜像设置后执行 update。博客构建完成或导入新镜像后执行 start blog 应用。

部署写操作有互斥锁，避免同时执行两个启动/配置流程。Ctrl+C 取消不会删除数据，已完成的步骤保留；用 status 查看后继续。非交互输入需要使用明确命令，CPA 官方安装器始终需要交互终端。

操作摘要记录在 `data/system/operations.jsonl`，不包含密码或官方安装器的交互输入。被捕获的错误输出写入私密的 `data/system/last-error.log`，便于排查一次性初始化任务。

整体备份或搬到另一台服务器时，先 stop all，再完整复制项目和 data，保留权限、隐藏文件及证书的相对符号链接。不要只复制数据库，也不要遗漏 state.json、secrets.json、博客配置、AI 加密密钥或 CPA data.key。

数据目录不要改成指向其他目录的符号链接。博客以 UID/GID 10001 运行，Linux 初始化器会设置其配置和运行目录权限。镜像不属于持久化数据，目标机器需重新拉取/构建或 docker load。

## 11. 排查

```bash
./bootstrap.sh status
./bootstrap.sh doctor
./bootstrap.sh logs gateway
./bootstrap.sh logs vpn
./bootstrap.sh logs cpa
./bootstrap.sh logs blog
```

- Docker 无法连接：检查 Docker Engine、当前用户权限。
- Compose 不认识 !reset：升级 Compose 插件到 2.24.4 或更高。
- 证书验证 403/404：检查 DNS、AAAA、80 端口、DNS 代理，以及 ACME 路径是否被外部服务拦截；不要反复重试触发 CA 限额。
- 网关页面显示 HTTPS 未启用：使用 HTTPS 域名访问，不使用服务器 IP 的 HTTP 地址。
- CPA 访问 502：确认官方安装完成，两个容器已运行，doctor 的网络检查通过。
- 博客镜像缺失：先 build blog 或 docker load，再 start blog。
- 博客 AI 错误：在后台核对普通 API Key、接口路径和模型；CPA 的账号及上游由 CPA 管理页面配置。
- VPN 连接后无网络：核对云安全组的 8443 TCP/UDP、客户端协议版本、Reality 目标以及服务器出站网络。
